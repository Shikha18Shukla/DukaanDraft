# DukaanDraft

**AI product-content studio for small Indian sellers — generated locally, on your machine.**

DukaanDraft helps a seller enter product details once and get a complete,
ready-to-publish content set: three distinct Instagram caption options, a
WhatsApp sales message, a detailed product description, key selling points,
hashtags, a call-to-action suggestion, a product title, and a marketplace
listing title. The content is generated by an open-weight AI model running
locally through [Ollama](https://ollama.com) — no paid LLM APIs, no cloud
inference, no database. Product details are never stored anywhere.

## Scope

- Flask backend with three endpoints (`/`, `/api/health`, `/api/generate`)
- Local Ollama integration using the `gemma3:4b` model (single non-streaming
  request per generation, with one bounded retry on malformed output)
- Category-aware prompting (fashion, footwear, jewellery, beauty, home,
  electronics, food) with strict accuracy rules — the model may only use
  facts the seller supplied
- Input validation and controlled error responses
- A premium, responsive landing page and product-content workspace with
  sample products, progress feedback, and per-section copy buttons
- Automated tests that run without Ollama or internet access

Not included (by design): user accounts, payments, a database, cloud
deployment, image analysis, or external social-media integrations. No
"Publish"/"Schedule" buttons — nothing pretends to integrate with platforms.

## Prerequisites

1. **Python 3.10+** (3.11 or newer recommended)
2. **Ollama** installed locally — https://ollama.com/download
3. The **`gemma3:4b`** model installed in Ollama

### Verify Ollama is running

```powershell
ollama list
```

You should see `gemma3:4b` in the list. If Ollama is not running, start the
Ollama application, then check again.

### Check or pull the model manually

```powershell
ollama list
ollama pull gemma3:4b
```

> **Important:** local inference only works while Ollama is running and the
> selected model is installed. The app never downloads models automatically,
> never starts a second Ollama server, and has no cloud fallback.

### Environment variables

| Variable           | Default                     | Purpose                              |
| ------------------ | --------------------------- | ------------------------------------ |
| `OLLAMA_BASE_URL`  | `http://127.0.0.1:11434`    | Local Ollama server URL              |
| `OLLAMA_MODEL`     | `gemma3:4b`                 | Model to use for generation          |
| `OLLAMA_TIMEOUT`   | `240`                       | Seconds to wait per generation attempt |
| `MAX_CONTENT_LENGTH` | `8192`                    | Max JSON request size (bytes)        |

## Run the application

```powershell
python app.py
```

Then open **http://127.0.0.1:5000** in your browser. Generation with the
local model typically takes **up to two minutes** per product — the UI shows
honest progress messages while you wait, and duplicate submissions are
blocked automatically.

## Run the tests

All tests mock Ollama — no model or internet access is required.

```powershell
python -m unittest discover -s tests -v
```

## API reference

### `GET /`

Renders the landing page with the product workspace and results studio.

### `GET /api/health`

Reports application health and Ollama connectivity.

```json
{
  "success": true,
  "status": "ok",
  "ollama": {
    "reachable": true,
    "model": "gemma3:4b",
    "model_available": true,
    "detail": "Ollama is reachable; model 'gemma3:4b' is available."
  }
}
```

When Ollama is down or the model is missing, the endpoint still returns
HTTP 200 with `success: false` and `status: "degraded"` — a health check must
never crash the app.

### `POST /api/generate`

Request body:

```json
{
  "product_name": "Cotton Kurti",
  "category": "Clothing & Fashion",
  "price": "599",
  "features": "Breathable cotton fabric, blue colour",
  "target_audience": "College students and working women",
  "language": "Hinglish"
}
```

- `product_name` and `language` are required; the other fields are optional.
- `category` may be a suggested category or any custom text; it guides the
  copy style (fashion, electronics, beauty, home, food, …).
- `language` must be `English`, `Hindi`, or `Hinglish`.
- Field lengths are limited (see `config.py` → `FIELD_LIMITS`).

Successful response:

```json
{
  "success": true,
  "content": {
    "product_title": "Indigo Cotton Kurti — Everyday Comfort",
    "instagram_captions": ["caption 1 — product-led", "caption 2 — lifestyle", "caption 3 — short and punchy"],
    "instagram_caption": "caption 1 — product-led (backward-compatible copy)",
    "whatsapp_message": "ready-to-forward WhatsApp message",
    "product_description": "detailed, structured description",
    "selling_points": ["Breathable cotton fabric", "Indigo blue colour"],
    "hashtags": ["#CottonKurti", "#EthnicWear"],
    "cta_suggestion": "honest, non-deceptive call to action",
    "marketplace_title": "Indigo Blue Cotton Kurti for Women — Daily Wear"
  },
  "model": "gemma3:4b"
}
```

`instagram_caption` is always a copy of the first caption option so older
consumers keep working.

Error responses always use `{"success": false, "error": "..."}` with an
appropriate HTTP status code (`400` malformed JSON, `422` invalid input,
`502` invalid model output, `503` Ollama unavailable / model missing,
`504` model timeout). Internal stack traces are never exposed to users.

## Privacy

- Inference goes **only** to the configured local Ollama endpoint. There are
  no cloud inference fallbacks.
- Product details are not written to any database, browser storage, or logs.
- No secrets are stored in source control; `.env` is git-ignored.

## Known limitations of local inference

- Generation requires a running Ollama server and the installed model; the
  app cannot generate content without them.
- `gemma3:4b` is a small model: generation takes up to ~2 minutes on a
  typical CPU, wording is less polished than large paid models, and
  occasional malformed output can occur — the app retries once and, if that
  fails, asks you to try again instead of showing broken content.
- The model may only use facts you supply; if you leave features blank, the
  copy will be thinner. More detail in = better content out.
- Throughput is modest: fine for a single seller drafting content, not for
  bulk or high-traffic use.
